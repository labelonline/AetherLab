# AetherLab — Release Management 2.0

Обновление переводит управление релизами на более цельный workflow: отдельная карточка релиза, модерация по полям, календарь, техническая проверка файлов и журнал действий.

## Что добавлено и изменено

- **Release Hub 2.0** — любой релиз из каталога можно открыть как отдельную страницу. Вкладки: `Обзор · Треки · Доставка · Финансы`.
- В шапке Release Hub отображаются обложка, название, артист, дата релиза, UPC и текущий статус.
- В `Обзоре` добавлен timeline: `Создан → Отправлен → На модерации → Исправлен → Принят → Доставлен`.
- **Модерация по конкретным полям** — администратор отдельно проверяет обложку, аудио, название, исполнителя, метаданные, трек-лист, авторов, Explicit, язык, Lyrics/TTML и AI-маркировку. Для каждого пункта можно выбрать статус и оставить отдельный комментарий.
- Старое отклонение одной общей причиной больше не является основным сценарием: кнопка детальной модерации открывает проверку по полям.
- Артист при редактировании отклонённого релиза видит замечания непосредственно возле проблемных элементов и в редакторе трека.
- **Календарь релизов** — режимы `Месяц / Список`, обложки и статусы прямо в календаре. Администратор видит релизы артистов, артист — свои.
- На Overview добавлен переход в календарь и счётчик релизов на ближайшие 30 дней.
- **Artwork & Audio Checker** запускается при загрузке файлов и до отправки на модерацию:
  - обложка: JPG/PNG, `3000×3000`, `1:1`, RGB/RGBA-проверка, лимит 10 MB;
  - аудио: корректный WAV, минимум `44.1 kHz`, `Stereo`, минимум `16-bit`, лимит 50 MB.
- При технической ошибке отправка релиза на модерацию блокируется до исправления.
- **Финансы внутри Release Hub** — вкладка показывает опубликованные строки финансовых отчётов, сопоставленные с конкретным релизом, и итоговую сумму в EUR.
- **Activity Log** — администратор видит кто, что и когда сделал. Есть фильтры по релизам, модерации, пользователям, поддержке, финансам и системе.
- В журнал записываются, среди прочего, решения модерации, изменения релизов, создание кабинетов, загрузка/удаление финансовых отчётов и статусы доставки.
- **Центр уведомлений полностью удалён из интерфейса и JS-логики**. Сохранены только локальные индикаторы непрочитанного у конкретных разделов (например, поддержка/новости), а email-оповещения не затрагивались.

## Новые / расширенные данные Firebase

Существующие релизы могут получить поля:

- `history` — история конкретного релиза;
- `moderation` — детальная проверка модератора по полям;
- `distribution` — статус доставки;
- `coverTechnical` — результат проверки обложки;
- `tracks[].audioTechnical` — результат проверки WAV.

Также используется корневой узел `activityLog`. Если текущие Firebase Rules не разрешают запись в `activityLog`, локальная история релиза продолжит работать, но глобальный журнал не будет полностью синхронизироваться между устройствами до обновления правил Firebase.

## Совместимость

Старые релизы не переписываются автоматически. Для старых файлов технические параметры появляются после новой загрузки/замены файла. Новые действия начинают формировать историю после установки этого обновления.

## Развёртывание

Загрузите **содержимое архива** в корень репозитория AetherLab с заменой совпадающих файлов. Версия ресурсов обновлена до `20260930-rm20`, чтобы GitHub Pages и браузер не держали старые JS/CSS из кэша.
